**Current State:**

*   If 'Grid' tab is active: Shows Grid loading indicator, Grid results via `<XYZGridDisplay>`, or Grid error message.
*   If other tabs are active: Shows placeholder text and links/previews for the *last* result generated (T2I, I2I, or Grid).

**Goal for the Right Column:**

The right column should ideally provide **context, supplemental information, controls, or visualizations** related to the *currently active workflow* in the left column, or serve as a persistent area for global tools/information.

**Ideas and Plan for the Right Column:**

Here's a breakdown of potential features, moving from simpler additions to more complex ones, aligning with the development phases:

**Phase 2/3 - Enhancing Current Workflows:**

1.  **Persistent Last Results Area (Refined):**
    *   **Idea:** Improve the current "Last Result" display. Instead of just one, maybe show the last 1-3 results regardless of type (T2I, I2I, Grid cell).
    *   **Content:** Small thumbnails, key parameters (seed, model), timestamp, buttons to "Load Params" (into the relevant form store) or "View Full" (switch tab for Grid).
    *   **Benefit:** Provides a quick visual history/reference without needing a full gallery yet.

2.  **Parameter Inspector / Documentation:**
    *   **Idea:** When hovering over or focusing on an input field in the left-column form (e.g., CFG Scale slider), display detailed information about that parameter in the right column.
    *   **Content:** Parameter name, description (pulled from Pydantic models via a backend endpoint?), typical ranges, links to relevant documentation or research papers.
    *   **Benefit:** Educates the user and provides context without cluttering the main form. Requires backend work to expose parameter metadata and frontend work to detect focus/hover and display info.

3.  **Real-time Generation Preview (Advanced T2I/I2I):**
    *   **Idea:** For T2I/I2I, display a low-resolution preview image that updates every few steps during generation.
    *   **Content:** An image element updated via WebSocket messages from the backend (which would need to decode latents periodically during the inference loop).
    *   **Benefit:** Provides immediate visual feedback, allows early stopping if results are undesirable.
    *   **Complexity:** High. Requires significant backend changes (pipeline interruption/callbacks, VAE decoding mid-loop, WebSocket communication) and frontend WebSocket handling. Likely Phase 3/4.

4.  **Selected LoRA/Embedding Details:**
    *   **Idea:** When LoRAs or Embeddings are selected in the left form, display more details about them in the right column.
    *   **Content:** For LoRAs: maybe metadata if available (base model, trigger words), link to source? For Embeddings: display trigger word(s).
    *   **Benefit:** Provides confirmation and context for applied modifiers. Requires backend to potentially read metadata from LoRA/TI files.

**Phase 3/4 - New Features & Visualizations:**

5.  **Latent Space Visualization Display:**
    *   **Idea:** When the 'Latent Space Viz' feature is triggered (perhaps from a dedicated tab or button), display the interactive plot generated by the backend (`/visualize/latent-space`) in the right column.
    *   **Content:** Interactive scatter plot (using Plotly.js, D3, etc.) showing projected latent points, with hover effects displaying image previews. Controls for UMAP parameters?
    *   **Benefit:** Central visualization area for this specific tool.

6.  **Parameter Sensitivity Visualization Display:**
    *   **Idea:** Similar to latent space viz, display the results (stats, heatmaps?) from the `/visualize/parameter-sensitivity` endpoint here.
    *   **Content:** Charts, tables, or heatmaps visualizing how output changes relative to input parameters.
    *   **Benefit:** Dedicated area for analysis results.

7.  **Experiment Browser / Gallery Preview:**
    *   **Idea:** While a full Experiment Browser might be its own page/route, the right column could show a mini-gallery of recent results from the database or previews of runs selected in a main browser view.
    *   **Content:** Grid of thumbnails, basic filtering/sorting options. Clicking could load details or parameters.
    *   **Benefit:** Quick access to past work.

8.  **Node Editor Preview/Controls (If Node UI Added):**
    *   **Idea:** If a node-based workflow editor is implemented (likely on the left), the right column could show previews of the output at the currently selected node or provide detailed controls for that node.
    *   **Content:** Image preview, parameter sliders/inputs specific to the selected node.
    *   **Benefit:** Essential for interacting with a node graph.

9.  **Global Queue Monitor:**
    *   **Idea:** A persistent section (maybe collapsible) in the right column showing the status of background tasks submitted via the `TaskScheduler`.
    *   **Content:** List of running/queued jobs, progress bars (if available), cancel buttons.
    *   **Benefit:** Global visibility into background processing.

**Proposed Plan for Right Column Evolution:**

1.  **(Now/Phase 2 Refinement):** Keep the current contextual display for the Grid tab. Refine the "Last Result" display for non-Grid tabs to show maybe the last T2I *and* last I2I result (or just the single most recent overall) with small thumbnails and a "Load Params" button.
2.  **(Phase 2/3):** Add the "Parameter Inspector" feature, fetching descriptions from the backend.
3.  **(Phase 3):** Implement the display area for Latent Space Visualization results.
4.  **(Phase 3):** Implement the display area for Parameter Sensitivity results.
5.  **(Phase 3/4):** Develop the mini "Experiment Browser Preview" / Recent Results gallery.
6.  **(Later):** Real-time previews, Node Editor context, Queue Monitor, depending on feature prioritization.

This approach keeps the right column relevant to the user's current activity or recent history, gradually adding more powerful tools and visualizations. What do you think of this direction?
